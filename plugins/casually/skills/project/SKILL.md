---
name: project
description: Prepare or update a shared Casually project, its service website and brand context, forms, draft LPs, history and review status.
---

Before reading or changing Casually data, [choose the business unit](../setup/SKILL.md#choose-the-business-unit): confirm it with `list_business_units`, tell the user its name, then pass its `businessUnitId` on every later call.

Use discovered Casually MCP tools and keep assets attached to the intended shared project.

1. Call `list_creative_projects` before creating a project. Read the selected project with `get_creative_project`; discover existing brands with `list_brand_guidelines` and forms with `list_marketing_forms` when needed. Use real IDs returned by Casually.
2. Create with `create_creative_project` or update with `update_creative_project_context`. Mutations use a unique `requestKey`; updates use `baseUpdatedAt` from a fresh read. Reuse identical inputs and keys after uncertain outcomes. On `CONFLICT`, read current state and reconcile the user's requested changes without overwriting unrelated work.
3. For a user-supplied public service LP, read the latest project and call `register_project_service_site` with its `baseUpdatedAt`, `requestKey` and URL. It saves the actual site reference for campaign generation. Website registration and draft work do not establish domain ownership. Publication or site changes must pass Casually's ownership checks.
4. Reuse existing forms where suitable. `create_marketing_form` accepts fields, validation, styling and spam settings; it does not submit or send mail. Read `get_marketing_form` before `update_marketing_form`, passing its exact `updatedAt` as `baseUpdatedAt`. Settings are patches: omit private notification/webhook settings rather than reconstructing them from redacted reads. Arrays replace in full. Preserve unrelated fields.
5. For a request to match a site's tone and integrate a form, register the source site first, then call `configure_form_integration` with `matchProjectBrand: true`, the form version and, for an existing LP draft, the page version. It matches saved site typography/colors, applies requested overrides and spam policy, preserves other LP blocks and returns the form embed plus website tracking setup. Country codes are ISO alpha-2; choose allowed/blocked countries and the unknown-country policy from the user's stated requirements. Never claim an IP country filter proves a person's nationality or eliminates all spam.
   For an existing custom HTML form whose design must remain intact, choose `embedMode: "existing"` and preserve its markup/CSS/consent links instead of generating a replacement or applying brand CSS. Apply returned form attributes, match saved input names/types, remove old submission handlers, block native server fallback, guard submission until ready and reconnect on client-side navigation. The site repository/CMS must be available to install these bindings. Missing controls block submission; a new field requires a matching site edit too.
6. Form views, starts, validation errors, attempts, confirmed submissions and abandonment are automatic on Casually LPs and external embeds. Full website page views/clicks/history use the separate returned tracking snippet. `DOMAIN_VERIFICATION_REQUIRED` requires the ownership tools; do not activate an unverified site. Install returned snippets only in an authorized editing target. A code snippet being returned does not establish installation.
7. Call `check_form_integration` with representative valid/invalid `sampleData` and country/hostname cases. This is a side-effect-free diagnostic, never a successful real submission. Confirm the installed page in the browser at desktop/mobile sizes, test error and success flows in an authorized test environment and inspect actual metrics. Do not submit real leads or send test notifications without authorization. Report captcha setup blockers honestly; keys stay in the organization's protected setup flow. Read `get_project_activity`, `get_project_review_status` or `get_project_performance` for project results.

Show project, preview and review links returned by the server. Never report configuration readiness as proof of visual fidelity or live measurement.

Never infer ownership from a reference URL, bypass tenant checks, put provider credentials in context documents, or fabricate brand evidence. Publishing, bulk email and approval use the campaign workflow; project preparation does not imply authorization to launch.
